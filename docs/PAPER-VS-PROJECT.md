# 论文 vs 开源项目 —— 两条成功标准

用户 2026-10-04 指出的区分:「论文的话我们是为了给一个合适的 insight,或者说提出了一个 claim,
至于开源项目,是要求有用。这里我感觉你弄混了。」

★ 在这之前我混得很具体:**我拿"有没有用"去筛"该不该当 claim"。** 于是一个被我们自己的数据
推翻的说法(编译降低决策熵)留在了标题候选里,只因为它好讲、大众能懂。这份文档把两条线分开,
并在每一处标出它们会做出**不同**选择的地方 —— 只有那些不同点能证明这不是换个词。

## 0. 两条成功标准

| | 论文 | 开源项目 |
|---|---|---|
| 成功标准 | **改变别人相信什么** | **被采用** |
| 靠什么赢 | 一个真的、反直觉的、可查的 claim | 解决真实问题,比别人便宜/好用 |
| 负面结果 | **好东西** —— 推翻流行的错说法 | 没人看 |
| "熵没降" | **一节论文**(反直觉的测量结果) | 不重要 |
| 一个数据集 | 不够,要 2–3 个 | 够,先解决一个真实场景 |
| 被引用的机制 | 一个**判据**,别人拿去测自己的系统 | —— |
| 被采用的机制 | —— | 一个脚本/一个契约格式/一个能省钱的开关 |

## 1. 论文:claim 候选,按证据强度排

| # | claim | 证据 | 强度 |
|---|---|---|---|
| **B** | 控制的不稳定**潜伏在数值里,不在决定里**;它只在策略去读那个数时变成行为 | 固定状态 761 次重复 **1 次翻转(0.1%)**;置信度抖到 0.44/0.40/0.46;一个读 `top()` 的 0.5 门限丢掉稳定正确的档位 ⇒ 4/20 题死,一次工具未调 | 🟡 强首次测量,**单数据集** |
| **A** | 判定层的有效变量是**判定与证据的因果耦合**,不是书写形式 | 改判 37/72、67/120 vs 0/72、0/72、1/120;对齐误伤后捕获 40.4% vs 11.1%,配对 23:6,p=0.0023,n=240;+6 条负面结果 | ✅ 已有;弱点:每边一个模型 |
| **C** | 不安全的是**"不确定性可以变成许可"**;单调性是防止它的最小条件 | 旧设计 unsure⇒拒绝杀 4/20;14 条测试 | 🟡 有测量,"最小条件"缺消融 |
| **D** | 基准自己的指标**看不见控制** | 单变量 A/B:1/20 vs 1/20,而工具调用 386→220、静默失败 15→8 | ✅ 干净,但属方法学 |

**建议的脊柱:B 主 claim + A 下半篇 + C 接口条件 + D 方法学一节。**
编译/不编译退回**架构**,判据(重复 × 稳定 × 证书)退回**工具**。

★ B 的技术防守(必须写进论文,否则会被攻):**状态键粗糙只会让稳定性看起来更差,不会更好**
—— 把两个真不同的状态并成一个,答案就会不同,于是被记成翻转。所以 **0.1% 是上界**。

## 2. 项目:卖别人今天就在疼的东西

| 疼在哪 | 我们的数 | 卖点 |
|---|---|---|
| 钱 | **74.3 次模型调用/题,其中 51% 落在已见过的状态上** | 声明掉那 51% |
| 审不动 | 89.6% 的决定是判官做的(这个数以前不存在) | 声明出的规则能拿给审计人看 |
| 修不动 | "稳定地错"的控制决定,今天没有任何指标看得见 | 声明出来 = 改一行 |
| 莫名的卡死 | 读置信度的门限 bug:判官 32/33 答对却被丢掉 | 诊断 + 一行修法 |
| 控制藏在 prompt 里 | —— | 契约是人能读、能改、能审的 |

第一句不该是"我们有判据",该是:

> **你的 agent 每一步都在重新决定一些本来不用决定的事。我们量了它花掉你多少(51%),
> 给了你一份能读的契约,还顺手指出一类你大概有的 bug。**

## 3. 两条线**会做出不同选择**的地方

| 问题 | 论文 | 项目 |
|---|---|---|
| "编译降熵"被推翻 | **写成一节**,是卖点 | 不提 |
| 手写契约 + dev 打分 | **限定**:要 pre-register,报改过几次 | **特性**:能读、能改、能审 |
| 判据(重复×稳定×证书) | 可被别人拿去用的**判据** | 跑在你自己日志上的**脚本** |
| 单调契约 | **接口条件**,要做消融证明其必要 | 一道防线:不会因"判官说不好"就停 |
| 数据集数量 | 不够,要 2–3 个 | 够,先做一个真场景 |
| 下一步 | 规范状态键 + 第二数据集 + 复现 B | 挑一个真场景把契约+引擎跑起来 |
| `tool.admission` 那个引擎检验 | 是"跨宿主"的证据 | 是"能省更多钱"的功能 |

## 4. 同时服务两边的一件事

**规范状态键 + 在第二个数据集上复现 B。**

- 论文:B 现在是一个数据集、20 题、761 行重复,立不住。
- 项目:"51% 花在重复状态上"是自检脚本的核心卖点,键不合法这个数就是错的。

★ 而且这类错**看起来很正常**:我自己刚用那个 413 行的记账 bug 把翻转率算成 30.3%,
真值是 0.1% —— **差 43 倍,而 30.3% 是个像样的数,不会有人怀疑它。**

## 6. 用户定的两条范围决定（2026-10-04）

### 6.1 `compile` 不进主 claim

> 「我们肯定能确认的一件事,就是这个 compile 这件事没有必要作为论文的主 claim 了。」

接受。理由本来就在数据里:**固定状态下决定翻转率 0.1%(1/761)**,没有熵可降;
编译真正买到的是成本、可审计、可编辑 —— **那是工程价值,不是科学主张**。
编译/不编译退回**架构**;判据(重复 × 稳定 × 证书)退回**工具**。

### 6.2 dev / RSI 那条线整条砍掉

> 「我们是否有必要做这个 dev 类似 rsi 的事情,我感觉混进来,故事有点杂乱。
>  主要的原因就是大部分的数据集并没有 dev 的 split,我们去划分肯定是要被喷的。」

接受,而且**砍它是安全的** —— 逐条查过保留的东西有没有依赖它:

| 保留的 | 依赖 dev 吗 |
|---|---|
| 每个数据集手写一份契约 | ❌ |
| 每个判定点声明 `decided_by` | ❌ **依据是"证据是不是证书"**,看证据的形态,不看数据 |
| 三条证书 | ❌ 证书是性质,不是统计量 |
| 单调契约 | ❌ 接口规则 |
| 每行记 `source` | ❌ |
| **B:有效控制熵 / 翻转率** | ❌ 只要同一状态重复问,不要留出集 |
| 声明率 / 抽样次数 / 翻转暴露 | ❌ 描述性 |
| **替换消融** | ✅ 要,但它不是 dev(见 6.4) |
| ~~发现→编译→看失败→再编译(RSI)~~ | ✅ 要 ⇒ **砍** |
| ~~`memoize`(缓存观测到的答案)~~ | ✅ 要(缓存表从数据里学)⇒ **一起砍** |

★ 顺带一条**事实**,它让"要不要切 split"这个问题失去意义:
**ALFWorld 是唯一一个真有三个划分的数据集**(`train` 3553 / `valid_seen` 140 /
`valid_unseen` 134);`ternary-judge` 只有 `test`;FTA 有 `pilot`(20)+ `test`。
而"大部分没有 dev"这个理由,在砍掉 dev 之后**从风险变成不相关**。

### 6.3 术语澄清:"后验"是什么意思

判据只有一条:**有没有"基于这个测量去做一个选择"。**

| | 有调参面吗 | 需要留出集吗 |
|---|---|---|
| **先跑再决定**(跑 dev → 看结果 → 定规则/判官 → 跑 test) | **有** | **要** |
| **先跑,然后量**(跑完读日志 → 描述不稳定在哪) | **没有** | **不要** |

B 是第二种,**而且构造上就是**:测完它什么都不选。所以你没法在一个你不做的决定上过拟合。

### 6.4 替换消融不算调参的条件

它看起来像"试两种、看哪个好",所以必须用报法规矩把它和调参分开:

| | 调参 | 消融 |
|---|---|---|
| 报什么 | **只报最好的那格** | **报全部格子** |
| 选择 | 挑赢的当方法 | 不挑 |
| 依据 | 结果分数 | **证据的形态** |

⇒ 硬规矩:**消融必须报全部格子,包括变坏的。** 而我们的选择依据指向证据、不指向分数,
在结构上免疫"在测试集上选"。

### 6.5 砍完之后的流程

```text
① 每个数据集手写一份契约（决策点因数据集而异）
② 引擎执行：能作证的用规则，其余用判官，判官只能收紧
③ 在数据集的**自带 split** 上跑，什么都不切
④ 报：原生分（原判分不动）+ 声明率 + 抽样次数/题 + 有效控制熵 + 翻转暴露 + claim×truth
⑤ 报：替换消融的全部格子（行为 / 成本 / 跨次方差）
⑥ 报：负面结果（含 4/20 那个门限 bug 与 413 行误标）
```

没有 dev,没有发现循环,没有 RSI,没有 memoize。
