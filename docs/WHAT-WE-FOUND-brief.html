JevLoop · 一页说明

Agent 会在没做成的时候，交出一份听起来做成了的回答

我们做了一个办法来量"再给它加一道判定，能不能拦住这种回答"—— 并且量到了一个有统计支持的效果。以下是最精简的版本。

一问题

真实事故长这样。一个 agent 被要求把某段代码抄进新文件，它最后交出来的回答是：

已完成。alpha.ts 中的 totalOf 函数已复制到新文件 summary.ts 中。

而盘上根本没有那个文件。难的地方在于：这句话读起来完全正常—— 语法正确、语气笃定、格式规范。任何"读一遍回答"的检查都过得去， 因为错误不在措辞里，在回答和现实之间。

工业界今天有三种做法并存：把流程写死成 workflow、让模型边做边自己判（agent loop）、 或者把判定拿出来单独做。三者都有人在用，但"哪种更不容易报捷"这句话一直只有轶事， 没有可比的测量。而且它们的差别不止一处——写死的 workflow 从不"答错"， 它在你没为它写过的情况上根本不存在；agent loop 什么情况都能应付， 代价是没人管它什么时候停、停得对不对。

更麻烦的是现有的评测发现不了治理层的价值。我们最早的对照实验跑了 81 个格子， 只观察到 1 个事件——在那个密度下"两组的平均差"在数学上就估不出来。

所以我们换了两件事：把判定从生成里拿出来，以及换一把尺子。

二做法

  • 判定不再住在生成里。不是"模型输出一句完成就结束"，而是生成之后另起一次判定， 它只读一份声明过的、有界的信息（只包含声明要看的几项，每一项排除都写明理由）， 由一个专门的决策模型来答。这正是这个项目的做法。
  • 尺子从"平均值"换成"混淆矩阵"。不看两组的均值差，看判定层批准的东西里 有多少是误导（假确认率），该拦的拦住了多少（捕获率），合法的活被错拦了多少（误伤率）。 这类比例在事件稀少时也估得出来，而且零事件时给的是上界，不是 0%。
  • 让所有对照组判同一个候选。每个任务只生成一份答卷，所有方案对它各自表态， 于是比较是配对的，可以用精确检验；同时有意识地把坏样本造出来， 而不是把样本量往 300 堆。

我们的对照组正好就是上面那条工程路线：写死在代码里（人做判断） → 融进生成（模型每步自己说） → 拿出来交给独立的判定模型。

这里有一处很容易读错，我们先说清楚

workflow 和 if/else 是同一个位置，不是两个。 两者都是"判定前移到写代码的时候、由人决定"。

所以"契约 vs 等价的 if/else"比的是写法——这一条我们做过了， 结论是政策层逐格相同、而且可证等价； 而"契约 vs workflow"比的是人的判断 vs 模型的判断——这一条还没测。

还有第三件事和位置无关：判定做几次、覆盖到哪里。 原始计划说这才是关键比较——"只在终点验证一次" vs "整个循环每一步都用契约"。 现在的实验只覆盖了终点那一次。

三效果

240 个候补（141 份该交付、99 份误导）。误导率约四成，是为了造出这类样本而设计的任务集上的比率。

中间那列最重要：

  • 加上判定层，基线会交付的误导里有 46 个被拒（配对检验 p < 0.0001）。
  • 专门的决策模型比"同一个模型配提示词"多抓到 23 个（23 : 6，p = 0.0023）。 也就是说，有效果的是专门的判定模型，不是"随便找个人再看一眼"。
  • 把两者的误伤代价对齐到同一水平（约 9–10%）再比： 专门的决策模型抓 40.4%，通用模型抓 11.1%——差 3.6 倍。

这张表里没有 workflow：那条臂我们建了，但只用它比过成本（模型调用次数、墙钟、token）， 没有按"诚实"这套指标比过。所以"workflow 和判定拿出来，谁更不容易报捷"今天还没有数据。

四两个反常识的发现

1. 通用的指令模型当判官，根本不看证据

我们把自己的主张拿去证伪：如果判定层真的在读它声称读的那份信息，那么把其中的证据换成 别的任务的证据，它的裁决就该变。结果——

判官换掉证据后改判的比例
专门的决策模型37/72、67/120 格
通用模型 + 提示词0/72、0/72、1/120 格

它抓得少不是"不会判"，是证据对它来说是装饰——它只看回答文本和任务文本。 顺带一个同样反常识的结果：换一个模型族并不必然更好。实测里异族判官抓得更多， 但误伤也多到超过连"拦下之后百分之百能修好"都容忍不了的上界，净为负。

2. 判定层的能力有上限：它不能比自己的证据通道更真实

当工具的谎言出现在判定层自己读的那份证据里（工具报告"已写入"、盘上什么都没发生）， 本研究里表现最好的闸门也只拦下 34%。三分之二的假完成照过。

证据链完整不等于证据链真实。

每一步都有记录、有指纹、可重放——这些是"完整"，是当前大多数工作当作卖点的那件事。 我们量出来的是：完整但被污染的证据链上，任何依赖它做判断的机制都被锁在 34%。

五里面真正的科学问题

完整性不等于真实性，那判定能力有没有一个可陈述的上界？

"垃圾进垃圾出"大家都认。但这里进的不是垃圾——是格式完美、来源可信、内容虚假的记录。 一个判定机制的能力上限，能不能由它所用证据通道的保真度来界定？ 如果能，这就是一个关于"判定"本身的界，而不只是工程问题。

价值来自"位置"还是"写法"？而"位置"又该怎么定义？

我们原本的主张是"把判定写成声明式的契约文件"——这一条被我们自己的实验证伪了： 政策层上，声明式契约和等价的 if/else 逐格相同，而且可以证明等价。

而工程界常说的"workflow vs agent loop"其实是另一根轴——它问的是判定由谁做 （人写死 / 模型边做边判 / 拿出来交给独立模型），不是怎么写。 两根轴混着谈，就会以为上面那个阴性结果推翻了"把判定拿出来"这件事，其实没有。 真正可证伪的对照是：生成之后是否存在独立的第二次判定、以及由谁读什么来做。

"独立性"到底是什么？

文献和我们的数据都否掉了两种流行说法：不是"多一次判定"（同一个模型自己判自己， 实测约等于没判），也不是"换个模型族"（实测反而更差）。 我们给出一个可以直接执行的判据：把证据换掉，看它的裁决变不变。 这把一个模糊的形容词变成了一个可检验的性质。

这类组件怎么算"合格"？

只报"抓到了多少"是可以被刷满的（一律说"没做完"就满分），所以必须成对报误伤。 而一旦要问"误伤多少算可接受"，就出现了标准工具覆盖不到的地方： 零假设检验在逻辑上无法证明"没有更糟"，而那个可接受的代价 不是统计量，是风险判断。 我们的做法是：先把代价上限定成 5 个百分点，再冻结门限，再用全新样本验算。 我们读过的五篇最接近的工作里，没有一篇做等价检验，也没有一篇做功效分析。

六老实说，还没确立什么

  • 效应量还不稳。四次同配置运行，捕获率分别是 44% / 73% / 82% / 34%。 正例不到十个的时候，两个方案的排序会翻方向。
  • "人的判断"那一端（workflow）没测过诚实指标，"判定做几次"那一根轴也完全没测。 这两块是原始计划里的重头，目前还是空的。
  • 四成的误导率是造出来的，不是真实系统的发生率——那三个写任务就是为此写的。
  • 衡量"好/坏"的尺子和被测的闸门同源。它自己已经误报过四次， 每次都是把一句老实的认输判成"不作声地交付没做完的活"。这直接决定上面所有数字的成色。
  • 而且就在最近一次，我们差一点就报错了一个数。 有一轮测出"误伤只有 3%，已经达标"，我们把它冻结成常量、换一批全新样本再验—— 结果是 9.2%。那个 3% 是 30 个样本上的噪声。 把这个过程留在文档里，比那个数字本身更有用。
  • 七个判定节点里只测了一个（交付闸门），其余六个还没有对应的实验。

一句话总结：把判定从生成里拿出来，用专门的决策模型读一份声明的证据， 确实能拦住一部分"报捷"——而且它明显比通用模型判得准；但它的能力被自己的证据通道锁死， 代价目前也还超出我们能接受的预算。
