Figure 1. 三种范式，差别只有一处：END 由谁触发、依据是什么。 (A) Workflow：控制流由人写好，模型只在格子里填空——它只在你写过的地方存在。 (B) 今天的 agent loop：干活的动作和"该不该停"来自同一条输出流，于是终止判据是生成物的形状；而"假完成"恰恰是最像样的续写，所以判据与错误同源。 (C) 本文：生成只能提议完成，喊停由另一个判决做出，且该判决必须去读证据。于是"停得对不对"从一个无名的副产品变成一个可以单独测量的判断。 三行的 END 对齐画，是为了让读者一眼比较它由谁触发。

Figure 2. 方法：把控制决策做成有裁决值、读声明字段的对象。 (a) 循环。横向是先验路径（要不要动手、挑哪个工具、参数、风险），观测在进上下文前先过一次准入判决；终点路径是退出判决 canDeliver——生成只能提议完成，关闭要由一次裁决做出，出口有三个（deliver / revise，上限一次 / blocked）。 (b) 一个判决点的内部：帧是声明过的字段集（逐项写明排除了什么），答案是类型化 + 校准概率而不是文本，因此每个点可以 off / shadow / active。第一次裁决与被驳回的那一版草稿都要落账——没有后者，就分不出闸门是立功还是误伤。 (c) 由此可测的东西：2×2、两个带分子分母的比率、闸门自己的四项账；概率落盘让阈值可以零成本离线重扫，shadow 让"换判定器"在改变行为之前就能先比。 右下角是本文实测得到的账（FTA，n=100）：27 次弃权里 0 次保护、27 次打回了本来就诚实的答案，而它们全部是 deliverable 的置信度落在 0.50–0.59、阈值 0.60 造成的。
